## 开团界面：时间筛选升级为日历自选（用户要求"更自由、能选更远的日期"）
- 原来只有两种：最近 N 天（1-60）/ 每周某天往前 N 次。老团（开团日久不复团的）只能靠月历扫才能捞到，用户要能直接选。
- 新增第三种模式 `calendar`（下拉"日历"）：月历弹层面板，周一开头、点格子加/减一天、‹ › 翻月、回到今月、最近7天/清空快捷、chip 上显示"已选 N 天"、提示行显示"将拉取 N 天（起~止）"。
- 约束：最多选 120 天（每天=服务端一个拉取窗口）；未来日期禁选（拉取是往回看）；默认今天及过去。
- **数据通路早就是通的**：`server.py` 的 `FetchParams.dates`（具体日期列表）一直支持，只是前端没用——`core.fetch_activities(dates=...)` 给了 dates 就忽略 days_range。这次只改了前端。
- ⚠️ **设计教训**：一开始想"点一个日期就自动拉"，但服务端 `/api/fetch` 有 `_fetch_lock`，并发直接 409——多选会变成拉取风暴。改成：显式「拉取所选」按钮 + 关面板时如有改动自动拉 + 切换模式时立即拉。
- ⚠️ 后台服务**跨会话会被回收**（今天发现 8765 空了，上次起的 8kl51I 没了）——重启：`env -u *_proxy /opt/homebrew/bin/python3 server.py` + run_in_background。
- index.html 单文件应用，前端改动免重启（页面每次从磁盘读）；改完用 python 提取 inline script + `node --check` 验语法（node 在 ~/.workbuddy/binaries/node/versions/22.22.2/bin/node）。

## 日历弹层「选一个就跳掉」Bug（用户报障，两层原因，已修+实测）
- **症状**：日历里点一个日期，面板就消失；切到日历模式时也会闪退。
- **原因①**：`startFetch()` 开头的 `closeAllDd()` 把 calPanel 一起收 → 切模式触发拉取时闪退。修：`closeAllDd` 不再碰日历；只有「点到外面」才关（document 监听里补 `closeCal()`）。
- **原因②（真凶）**：`calToggle → calRender()` 用 `innerHTML=''` 重建网格，**被点的按钮当场脱离文档**；事件继续冒泡到 document 时 `e.target.closest('.filter-wrap')` 在游离元素上找不到祖先 → 被误判「点到外面」→ 关面板。修：`#calPanel` 上加 `click → e.stopPropagation()`，面板内点击不冒泡。
- **验证**：agent-browser 技能实测（`select "#rangeMode" calendar` + `eval` 断言 className）：切模式/连点3个日期/翻月/点「拉取所选」后面板均保持 `cal-panel open` 且拉取进度正常；点 body 才关。
- **通用教训**：「点击处理里重建触发元素的 DOM」×「document 级 closest 判断里外」= 游离元素坑。重建 DOM 的事件源要么 stopPropagation，要么别在 handler 里重建它。

## 日历模式改为纯手动拉取（用户：选好了不要自动拉取）
- 拆掉两处自动拉：① `applyRangeMode` 里 `if (doFetch && rangeMode !== 'calendar') startFetch()`——切到日历模式不再触发拉取；② `onRangeChipClick` 关面板时的 dirty 自动拉——删除，`calDirty` 变量整个移除。
- 现在日历模式只有三个拉取入口：「拉取所选」按钮、顶部「刷新列表」、以及切回「最近/每周」模式（后两者保留原有自动拉逻辑）。
- agent-browser 实测：切模式/点3日期/关面板后 `#fetchProgress` 均为 `progress-area`（无 show）；点「拉取所选」后 `progress-area show`，状态行显示"拉取中 (页 10-08 第1页)"。
