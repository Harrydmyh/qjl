## 要把售后推到企业微信群（消息推送 / 原「群机器人」）

官方文档确认（2025/08/07 版，已改名 **消息推送**）：
- 创建：群聊右上角 → 消息推送 → 新建 → 拿到
  `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=<uuid>`。**无需应用/IP 白名单**。
- 8 种消息类型：text / markdown / markdown_v2 / image / news / file / voice / template_card。
- text content ≤2048 字节；**markdown content ≤4096 字节**（三种颜色：info 绿/comment 灰/warning 橙红）；
  markdown_v2 语法更全（表格、图片）但**不支持颜色也不支持 @群成员**，且老客户端降级成纯文本。
- text/markdown 支持 content 里写 `<@userid>` @成员；也可用 `mentioned_list` / `mentioned_mobile_list`。
- **频率：每个机器人 ≤ 20 条/分钟**（40 条售后必须分批 + 限速）。
- 素材上传：`webhook/upload_media?key=KEY&type=TYPE`，multipart 字段名 `media`，media_id **仅 3 天有效**。
- 错误：webhook 不对时返回 `{"errcode":93000,"errmsg":"invalid webhook url"}`，HTTP 仍是 200 —— 别只看状态码。

### 鉴权（2026-10-11 确认）
- **消息推送（群机器人）不鉴权**：URL 里的 `key` 就是唯一凭证，不需要 access_token、也不需要配 IP 白名单。
  实测拿假 key 打过去：`HTTP 200` + `{"errcode":93000,"errmsg":"invalid webhook url"}`（没有任何"缺少凭证"的提示）。
- 副作用：key **≈ 密码**，泄露即任何人可往群里发垃圾；**无过期、无 IP 限制**，唯一补救是**删掉机器人重建**。
- 对比 **自建应用服务端 API**：`GET /cgi-bin/gettoken?corpid=ID&corpsecret=SECRET` → `access_token`，
  官方**明确要求：不要把 access_token 下发到前端，所有请求由后台发起**（与我们「必须从 server.py 发」一致）。
  有效期 `expires_in` **正常 7200 秒**，要自己缓存并做失效重取，**不能频繁调 gettoken 否则会撞频率拦截**。
- 目前售后推送场景用群机器人就够；只有要「给指定成员发应用消息 / 撤回 / 拿成员列表 / 定时群发 / 交互回调」
  才需要升级成自建应用。

## 🔑 企微有真机器人：智能机器人（21:2x 官方文档核实，比逐个群建 webhook 强得多）

用户有几千个群，逐个建 webhook 不现实。**答案在官方文档：智能机器人**，比 webhook 高一个维度。

- 文档：path/101463「智能机器人长连接」（**更新于 2026/05/25**，是相当新的能力）、
  path/101468「API模式机器人」、path/101521「自建应用与智能机器人的对接」。
- **一套凭证管所有群**：机器人是 **BotID + Secret**，不是每群一个 webhook key。
- **长连接**：`wss://openws.work.weixin.qq.com`，发 `aibot_subscribe` 带 BotID/Secret 校验。
  🔥 **不需要公网 IP**（文档明确列为推荐场景：内网部署），正好适合本机/阿里云都行。
  还有 Webhook（短连接）模式，但那要公网回调 URL。
- **主动推送**：`{"cmd":"aibot_send_msg","headers":{"req_id":...},
  "body":{"chatid":"CHATID","chat_type":2,"msgtype":"markdown","markdown":{"content":"..."}}}`
  - `chat_type`: 1 单聊 / 2 群聊（建议显式给）
  - **markdown 上限 20480 字节**（webhook 只有 4096）
  - 还支持 template_card / file / image / voice / video；`feedback.id` 可做消息反馈回调
- **频率是按「会话」算的**：每个会话 **30 条/分钟、1000 条/小时** —— 不是按机器人，
  所以群多也不堵。（对比 webhook：每个群一个 key，每个机器人 20 条/分钟）
- ⚠️ **同一机器人同一时间只允许 1 条长连接**，新连接会踢掉旧的（收到 disconnected_event）；
  要高可用的话走主备，不要并发多连接。
- **chatid 怎么来**： `aibot_event_callback` / `aibot_msg_callback` 的 `body.chatid`
  （**仅群聊时返回**）+ `body.chattype: single|group`。官方原话：群聊 chatid 从「相关回调事件中获取」
  → **机器人得先被拉进那个群**，之后有人 @ 它/进会话，我们就自动拿到并记住 chatid。
- Python 有官方 SDK：`aibot-python-sdk`。

1. 用新凭证拉 7 天：**221 raw → 206 条**，但 **`hasFollowRelation` 全 False**
   （`followEarning` 全为 **null**、activityType 全 = 10 → 全是**团长自营团**）。
   按 core.py:432-435 的注释，这类**没有跟团关系，硬开必失败**。
2. **`upStreamTypeList=[3]`（品牌供货活动 = 唯一可开团的那类）返回 0 条** ——
   7 / 30 / 60 / 180 天窗口**全是 0**。
3. 定向搜索旧账号见过的 6 个供应商（益能云天、飞玥穿搭号…）→ **全部 0 条**
   → 这个账号跟那些供货团**没有帮卖关系**。
4. 拿它自己看到的 4 个供应商反查 `[3]` → 也全 0。

⇒ **没有一条可跟团的活动**。硬跑 206 条会全部失败，还会对 206 个团发无效请求（风控风险）。
**因此未执行开团，也未把新凭证写进 config**（写进去会顶掉旧账号、且仍无可开团的）。

### 复用结论
- 判断「某账号能不能帮卖」的最快方法：直接 `_fetch_one_page(ups=[3])`，
  **返回 0 就说明没有可跟团的活动**，别再去翻 followEarning（列表接口只给 actId，详情才带）。
- 换账号后 `open_log` 是**旧账号**的记录 → 5 天冷却会串号（旧账号开过的会误挡新账号），
  换号前要先决定 open_log 怎么处理，这点以前没注意。

### 权限判据（实测三种结果）
- `activityType=10`（团长自营团）→ **`code 5830`「您没有帮卖权限，请联系团长」**
  → 广场拉到的 206 条全是这个类型，**一条都开不了**（我最初的判断是对的，只是理由不同）。

### 开团请求体的构造（已验证 21/21 成功）
顶层 17 个键，大部分从 for_leader 响应直接取：
- `pactId`←data.actId、`ghGroupId`←自己的 ghId
- `addActivityParam`←{isDoubtSubmit:false, activityName/startTime/endTime/displayType ← activityDTO,
  activityStatus:10, **ghViewType:20**（注意不是 DTO 里的 10）}
- `activityInfoParam`←{activityDetail, bgImgId ← activityInfoDTO, phone ← 见下}
- `activitySettingsParam`←**activitySettingsDTO 为基础 + 用成功样本的键补齐缺失项**
- `activityGoodsList`← 转换：`mutiActGoodsInfoDTO.actGoodsSkuPropertyDTOS[]` →
  `mutiGoodsParamList:[{actGoodsId, groupBuyPrice, totalStock, evaluationPrice:0}]`，
  父级取 `actGoodsId` + `actGroupBuyPrice`，另加 `actGoodsExtStatus:10`
- `actLogisticsInfos`←只保留 `logisticsModel` + `actLogisticsAttrs[{attrType,attrName}]`（多带 actAttrId 也行，但要清洗）
- 常量：`logisticsExtension:10, activityGroupDeliverIdList:[], isSelectAllGroupDeliver:1,
  selectActivityGoodsIds:[], actDiscountParam:{discountItemParams:[]}, isDoubtSubmit:false,
  isCertificationSubmit:false, labelIdList:[]`
- 手机号：`GET /activity-accessory/activity_input/get_user_input?ghId=<ghId>`
  → `data.inputMap["210"]` 数组里找 `{"phone":"..."}`（**必须带 ghId 参数，否则返回空**）

### ⚠️ 两个坑（都是真踩过）
