# 2026-11-15 企业微信「6048 客户群自动群发」调研

## 结论先说
- 用户口中的「3000 余个群」实测是 **6048 个企微客户群**（外部群，成员是微信用户/团长）。证据：后台 客户联系 → 客户群 页显示 `6048 group chat(s) in total`，导出文件也是 6048 行。
- **客户群不能加群机器人（webhook）**，群设置里没有该入口，官方明确「外部群不支持消息推送」。webhook 路线对这批群彻底不成立。
- 官方唯一合规通道 = 客户群群发接口 `externalcontact/add_msg_template`。关键能力（易被误判为不可用）：**支持 `chat_id_list`，一次最多 2000 个客户群，指定后群主无需再挑群，只需点一次「发送」**（需企微终端 ≥ 4.1.10）。每群每月可接收条数 = 当月天数（即每天 1 条，可在群发助手规则里调）。

列：群名 / 群成员数 / 群主 / 群主部门 / 建群时间。**导出不含 chat_id**。
- 群主仅 7 个：桂花汤团 2630、芝麻汤团 2168、小顺 819、小米 207、汤团好物 121、小丰 96、秋丰 7

## 当前唯一卡点：企业可信IP
- 自建应用（AgentId 1000020，名称「123」）在「客户联系 → 客户 → Apps that can call APIs」里**是灰的不可勾选**，标 `Trusted IP not configured`。
- 配置企业可信IP 又要求先有「**可信域名**」或「**接收消息服务器URL**」（应用详情页 企业可信IP 弹窗内 textarea 是 disabled，提示原文 "Before configuring the company's trusted IP, please Set trusted domain name Or Set the server URL for receiving messages"）。
- 可信域名必须是**已备案且备案主体与「秋丰合顺」一致或关联**的域名，填 IP 一定报「域名主体校验未通过」。
- 旧应用 AgentId 1000009 / 1000019 无企业可信IP 字段（2022-06 前创建），调客户联系接口一律 60020。
- 未解决前 `externalcontact/groupchat/list` 拿不到 chat_id。

## 其他踩坑记录
- 后台内部接口 `GET /wework_admin/customer/getGroupChatList?off_set=&limit=&page=&create_ts_begin=&create_ts_end=` 用登录 cookie 可翻全量，返回 `roomid`（数字内部ID，如 10887417995792172）、`vid`（群主内部ID）、`member_count`、`total:6048`。**roomid ≠ 群发接口的 chat_id（wr 开头）**，不能直接拿来发。
- 后台客户群页有「导出为 Excel 文件」，导出完成会打点 `is_export_succ:1, export_finished:6048`，文件落到 ~/Downloads/Customer Group List.xlsx。
- 登录后台用 agent-browser：必须用固定包装脚本 `ab.sh`（固定 `--headed --profile /tmp/qjl-browser-profile --restore qjlwecom --proxy-bypass ...`），否则参数变化会触发浏览器重启、丢登录态。cookie 注入不可行（企微有设备指纹，页面加载即清 wwrtx.sid/vst/vid）。
- Secret 只能发到企微 App「企业微信团队」会话里看，网页永不显示明文。

## 空壳群筛查（最终口径：637 个，不是 658）
**`foreign_mem_cnt` 不可单独用作判据**——它只统计「微信外部联系人」，别家企业企微用户（售后对接、供应商、平台客服）不计入。用户当场纠正过一次。
正确做法：拉 `getRoomMemberList` 看每个成员的 `corpid`。
- `corpid == 1970325199978193` → 自己人（秋丰合顺）
- `corpid == ''` → 微信客户
- `corpid 其它值` → **别家企业企微用户（外部人，但 foreign_mem_cnt 不计数）**

优化：`foreign_mem_cnt > 0` 的群必然有外部人，无需逐个查。**只查 `foreign_mem_cnt == 0` 的 658 个群**，成本从 6048 降到 658。
结果：**637 个真·纯内部群 + 21 个被误判的群（有外部企微）**。
- 那 21 个几乎全是售后/对账/对接群（群接龙科技、广州拼了-张大妞、雅尼克-今生、杭州花怒-胡大班长、美维口腔-维乐齿科……），**绝对不能当空壳剔掉**；其中「企业微信续费」「测试」「珍岛集团」「推宝科技」等属工具/推销群，可另议
- 我方主力账号 8 个 vid：桂花汤团、芝麻汤团、小顺×2、小丰、汤团、汤团好物、小米
- **没有「不含我方人员」的群**（658 个里 noSelf=0）
- 637 个纯内部按群主：桂花 213、芝麻 184、**汤团好物 121（该号 100% 空壳）**、小顺 100、小米 14、秋丰 4、小丰 1
- 按人数：153 个 1 人群、232 个 8 人群（全员到齐），其余 2~7 人
- 清单：`data/wecom/真空壳群_纯内部_20261115.csv`、`data/wecom/有外部企微_误判修正_20261115.csv`，按群主拆分在 `data/wecom/真空壳_按群主/纯内部群_*.csv`
- 剔除 637 后 6048 → **5411 可发**，群发任务 9 → **7 个**（桂花 2417=2 个、芝麻 1984=1 个、汤团好物 0 个）

## 后台内部接口速查（登录态 cookie 可直接 fetch）
- 群列表：`GET /wework_admin/customer/getGroupChatList?off_set=&limit=200&page=&create_ts_begin=1646236800&create_ts_end=1794745408&accurate_keywords=` → `roomid/adminName/member_count/foreign_mem_cnt/createtime`
- 群成员：`GET /wework_admin/customer/qun/getRoomMemberList?off_set=0&limit=600&roomid=<roomid>&page=1` → `members[].vid/name/corpid/corp_name`
- 群详情：`GET /wework_admin/customer/qun/getRoomInfo?roomid=<roomid>`（只有群主信息，无成员）
- **成员接口限流很硬**：并发 10、连续请求会直接 429「请求服务器过于频繁」（要等 3~5 分钟）。安全速率并发 3~5 + 每轮 sleep，`agent-browser eval` 单次硬超时 **30 秒**，所以每批不能超过约 60 个群

### 解散：官方没有任何接口
企微技术支持原话「暂无接口支持」「解散都是必须通过客户端，且必须逐个解散」。客户端路径：群设置 → 群管理 → 解散群聊。**不能 API 批量解散**，只能群主手动。
策略建议：不解散，群发时排除即可（零成本、可逆）；解散只对「内部同事群列表清爽」有收益，且聊天记录不可恢复。

## 批量换群主的硬上限（2026-11-15 核实）
- 在职转群主 `externalcontact/groupchat/onjob_transfer`，离职版 `groupchat/transfer`
- `chat_id_list` 一次 **1~100** 个
- **一个群主的群，每天最多转 300 个给同一个新群主** ← 真正瓶颈
- **90 自然日内每个群最多转 2 次**
- 新群主须：配客户联系功能 + 实名 + 激活企微；新老群主近一年内至少登录过一次
- 后台路径：客户联系 → Management → Inheritance from Existing Employees。只能「按成员整体转」（会连客户一起转），或「按群名搜索逐个挑」（6048 群不现实）
- 结论：**为群发不需要换群主**（2000 是任务容量上限，不是人管群上限），拆任务即可
