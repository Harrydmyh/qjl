## 确认「开过的活动下次刷新会不会被去掉」——机制是 isFollow，不是 5 天冷却

### 实测证据
用户已在 2026-09-17 21:59 / 22:02 / 22:05 成功开出 3 个团（`data/open_log.json` 有 3 条 ok，
且都记录了 `goodsIds`，说明 goodsId 冷却那版代码已生效）。
拿这 3 个 actId 重新查详情接口，**开出团后 `isFollow` 从 False 翻成 True，`hadHelpSale` 保持 False**：

```
2609170486953247  hadHelpSale=False isFollow=True  totalOrders=1
2609170470086749  hadHelpSale=False isFollow=True  totalOrders=0
2609170465742924  hadHelpSale=False isFollow=True  totalOrders=0
```

### 判定分支（core._finish_fetch）
```
new_raw    = not hadHelpSale and not isFollow   → isFollow=True 直接出局
reopen_raw = hadHelpSale=True → 成交≥1 → 5 天冷却
其余        → 两条池子都不进 → 整条消失
```
所以**已开过的活动会消失，靠的是 isFollow，而且是永久的**（不是 5 天后又能看到）。

### 关键连带结论
**5 天冷却在实践中几乎没用上**：它只作用于 `reopen_raw`，而那批 100% 是 B 类（开不出来）。
`isFollow` 已经覆盖了「我开过的」这条主要场景。

### 两个注意点
1. **清空历史记录不影响 isFollow 这条保护**（服务端给的，删本地日志也照样排除）；
   但复开那一路的冷却数据在本地日志里，清掉会失效（不过那批本来也开不出来）。
2. **同款换 actId 会重复出现**：`isFollow` 绑在 actId 上。同一商品若被别的团长重新开团（新 actId），
   新 actId 的 isFollow=False → 会作为「新活动」再次出现，可能对同一款商品开第二次团。
   ⚠️ `dedup_by_goods` 救不了：它在**已经剔掉 isFollow=True 之后**才去重，此时池子里只剩新 actId。
   `parse_item` 里的 `daysSinceOpen` 其实已经用 goodsId 算出来了，只是前端只在 reopen 行显示。
   → 建议：把 goodsId 冷却扩展到 new 池（用同一张 `last_opened_goods` 表），或在新活动行显示「同款 N 天前开过」。
