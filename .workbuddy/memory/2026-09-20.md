## 22:00 修「开 N 个」不随筛选变化（用户报：筛完只剩 11 条，按钮还是「开 31 个」）

### 根因
`updateSelUI()` 里按钮文案 = `activities.filter(a => selectedIds.has(a.actId))` 的可开团数，
即**只认手动勾选，完全不看当前筛选**。而 `syncOpenTab()` 只清理「已不在 activities 里」的勾选，
**被筛选条件排除、但仍存在于列表里的勾选不会清** → 数字看起来"永远不变"。
（与早先「右上角计数不跟筛选联动」是同一类 bug 的第二次出现。）

### 改法（都在 index.html）
1. `renderActivities()` 里 **勾选跟随当前视图**：`visible` 算出来后，
   把不在 `visible` 里的 `selectedIds` 删掉，记 `selDropped`；
   右上角计数追加 `· 已取消 N 个筛外勾选`（黄色 + tooltip），不静默丢弃。
2. `updateSelUI()` 里 **按钮始终显示"真的会开几个"**：
   - 有勾选 → 勾选里可开团数（勾选已裁剪到当前视图内）
   - 无勾选 → 当前筛选结果里可开团数（与开团面板默认范围一致）
   - 筛选结果为空 → 隐藏按钮
