## 08:43 用户问：Charles 能不能布在 Linux 当脚本用？模拟微信进小程序拿 token 能不能脚本化？

**结论：不能全自动，微信那一步必须真人 + 真客户端；但中间环节可以自动化。**

### 为什么不能（技术上的硬约束）
- token 由群接龙后端在**微信登录之后**签发。小程序登录走 `wx.login()` → 拿一次性 `code`
  → 换 session。这个 `code`：**只能由该 appid 的真实微信客户端产生**、**一次性**、
  **约 5 分钟失效**、**绑定用户的微信会话**。无头脚本产生不出来。
- 硬要绕过 = 伪造微信身份 → 违反微信/群接龙用户协议，且必撞风控（短信验证、滑块、封号）。
  **不做这种方案。**
- **代理跑在哪不是关键**：这份抓包（#2 请求头）里 `user-agent` 是
  `Mozilla/5.0 (Macintosh; Intel Mac OS X 10_15_7) …`、`referer` 是
  `https://servicewechat.com/wx059cd327295ab444/2325/page-frame.html`
  → 说明是**在 Mac 上的微信客户端（webview）里跑小程序**抓到的。
  **服务器上没有能打开小程序的微信客户端**，所以把 Charles/mitmproxy 搬到 Linux 并不解决这一步。
- 另外 **Charles 本身不适合脚本化**：它是 GUI 抓包工具（「看」流量），不产出 token；
  Linux 版还要图形环境。要脚本化应该用 **mitmproxy**（有 Python addon API）。

### 可以自动化的部分（推荐方案）
1. Linux（或任意常开机器）上跑 `mitmdump -s addon.py`，无头运行。
2. 手机/微信客户端把代理指向它（一次性配置 + 装 mitmproxy CA）。
3. addon 只在 host 为 `apipro.qunjielong.com` 的请求里找 `authorization` 头
   （或 URL 上的 `Authorization=` 参数 —— #20/#197 就是这种），解析 JWT。
4. **只在「新 token 的 exp 比当前 config 里的更晚」时才写回** `data/config.json`，避免抓到旧的。
5. 配合「到期预警」：到期前提示 → 用户只需打开小程序一次 → 其余全自动。

**一句话**：把「每 48 小时手动复制粘贴 token」压缩成「每 48 小时打开小程序一次」，其余自动化。

## 手机端：全选入口缺失 + 新增按供应商排序（用户反馈）

### 根因
手机端 `@media (max-width:768px)` 里 `thead { display: none }` —— 表头被整个隐藏，
而**全选复选框 `#selectAll` 和所有排序表头都在 thead 里** → 手机上全选、排序**两个入口全消失**。
（工具栏里虽有 `#selAllBtn`，但它在横滑区很右边，且 `hasAny ? 'none' : ''` 有勾选时就隐藏。）

### 改法
新增 `.list-bar`（「选择条」），基础 CSS `display:none`，只在窄屏显示：
- 活动列表：`#mSelectAll`(checkbox) + `#mSelAllLabel`(全选 N) + `#mSelCount`(已选 N) +
  `清除` + `#sortSel`(排序下拉) + `#sortDirBtn`(↑↓)
- 开团面板：`#mOpenAll` + `#mOpenCount` + `清除`
- 状态与表头双向同步：`updateSelUI()` / `updateOpenStat()` 里回写 checked/indeterminate/计数；
  `syncSortBar()` 在 `renderActivities()` 里把 sortCol/sortDir 反映到下拉与方向按钮。

### 按供应商排序（新能力）

`String(a.ghName).localeCompare(b.ghName,'zh-Hans-CN')` —— **必须用 localeCompare，
