## 继续排查同款重复 → 升级同款判定为三条判据

**用户报的漏判样本**（今天挑的）：`.孟孟` 的「NOUSAKU 深睡睡衣套装男款」¥149
vs `斗不斗®` 的「【26秋冬-女款】NOUSAKU无感深睡睡衣长款LK-369」¥139。
核对后确认是同一款：两条活动都含 男款¥149 / 女款¥139 / 儿童款¥129 三个规格，
只是 goodsId 不同（不同供应商各自导入）、标题被大改。

### 为什么旧规则漏
1. `parse_item` / `_goods_groups` 只取**第一个**商品名做判定（这条数据里第一个还是「男款」）。
2. 就算用全部名字，两条的归一化名字集也没有包含关系（Dice 仅 0.52）。

### 改了什么（`core.py`）
- `_item_goods_name` → **`_item_names`**：取全部规格名。
- `_containment_pairs` 改为按「活动 × 全部名字」建 8-gram 索引，去重后返回活动对。
- 新增 `_names_same`：匹配到的名字要占少方 **≥50%**（`_NAME_OVERLAP_MIN`）。
  必要性：`骄傲美食` 的三个**不同主商品**活动都挂了同一个换购件
  「99秒杀福利京都板前特调鲜甜烧肉汁」，不加比例限制会被并成一条。
- 新增**多规格价格指纹**（`_MULTI_SKU_MIN=2` / `_MULTI_SKU_SIM=0.45` / `_MULTI_SKU_BUCKET_MAX=300`）：
  规格数相同 + 价格组合完全相同 + 名称集 Dice ≥0.45；两边都带款号且互不相交时**否决**
  （正是它挡住「欧迪芬家居服 XH3874×5」误并到「XH3873×5」）。
- `_finish_fetch`：新增 `merged_extra`，把被合并来源的 goodsId/商品名也计入 5 天冷却判定
  —— 去重后留下的那条未必是我开过的那条。
- `parse_item` 增加 `skuCount`。

## 顺带修掉两个真 bug + 新增「标记已开过」

用户没回答「4 条从哪来」，于是按现有信息把能确定的都修了。

### Bug 1（重要）：open_log 从来没写 `goodsNames`
`server.py` 的开团任务里算了 `goods_by_act` / `names_by_act`，但 `append_log(...)` 里
**只写了 goodsIds，`names_by_act` 一次都没用**。后果：**新开的团在日志里没有 goodsNames**，
5 天同款冷却就只剩 actId / goodsId 两种命中方式，「同款换个供应商重新上架 / 改了标题」
就认不出来 → 同一款被反复开。历史 261 条是后来回填过 goodsNames 的，所以之前没暴露；
**一旦有新开团，冷却能力就静默降级**。
修：抽出 `_goods_meta(actIds)`（先查 activities.json，查不到现打详情），
成功开团时写入 `goodsIds` + `goodsNames`。

### Bug 2：批量详情接口「整批同生共死」
`query_list_by_act_ids` **批里只要有一个无效 actId，整批返回 0 条**
（实测 `[有效]`→1 条，`[有效, 无效]`→0 条）。拉广场时 actId 都来自列表接口所以没踩到，
但手动粘贴历史 actId 会踩。
修：`_fetch_details_batch` 整批失败时**逐个重试一次**救回有效的那些
（原请求下沉为 `_post_detail_batch`）。

### 新功能：列表行「标记已开」按钮
- 后端 `POST /api/log/mark {actIds:[...]}` → 写一条 `status=ok` + `manual=True` 的日志，
  自动带上 goodsIds/goodsNames。拿不到商品信息时返回在 `weak` 里提醒用户。
- 前端每个活动行加了「标记已开」小按钮（uiConfirm → 接口 → 本地置
  `recentlyOpened=true, daysSinceOpen=0` 并重渲染，立刻变成冷却状态）。
- 用途：**工具看不到你自己在群接龙里开的团**（实测全库 ghId==自己账号的活动数=0，
  广场接口也不提供自己的团列表），只能靠这一步补进来。

## 用户补了标题 + 款号 `MY-0157` → 定位到第 4 个来源，并加了「已跟过」默认不勾选

用户给的标题末尾有 **`MY-0157`**。用**服务端关键词搜 `MY-0157` 精确命中 1 条**：
- `2609140181839554` **狂奔的小绵羊💨💨💨** 09-14 18:03:16，`goodsId=301136845`，
  goodsName「减龄手绘“一颗棃子”印花卷边毛圈卫衣」¥69，**`isFollow=True`**。
- 注意：它的 goodsId 与另三家（301348294）**不同** —— 同一款货、不同供应商各导入一次。
- 另 3 家 actName 里**没有** MY-0157，只有小绵羊这条有。
- 4 条并进同一组：小绵羊≈益能云天（名字包含，dice 0.88），益能云天≈加强Styling≈吧啦小仙子
  （goodsId 相同）；小绵羊↔吧啦小仙子靠**链式**（dice 0.67、无包含、goodsId 不同）。
- `foldActIds` 全窗口 0 条非空 → 平台不提供「同活动折叠」，别指望它。

### 关键结论：`isFollow` 是工具唯一能看到的「我自己开过」的证据
用户报的 4 个时间点不在广场（复查：`MY-0157` 全域只有 1 条、`狂奔的小绵羊` 09-19~09-24 共 20 条
无此款）→ 那 4 条是**用户自己在群接龙里开的团**（标题继承自源活动，所以「重复的几条都是这个标题」）。
而源活动 `isFollow=True`，正是平台在说「你已经开过它」。

**改动**：`parse_item` 增 `alreadyFollowed = bool(isFollow)`；前端开团面板默认勾选改为
`isDefaultOpenPick = !isOpenBlocked && !alreadyFollowed` —— 已跟过的行**仍然显示、仍然可勾**，
只是不再预勾；统计里单独显示「已跟过 N 条默认未勾选」。这样即使开团是在工具外发生的，
下次也不会被默认再开一遍。
- 实测今日 289 条里 **26 条**是 alreadyFollowed 且当前都可开 → 以前会被预勾选，现在默认不勾。
- 兼容：旧缓存数据没有 `alreadyFollowed` 字段时仍然按「可勾」处理（不会误伤）；
  必须重新拉一次列表才会带上这个字段。
- 前端判据单测 6 个用例全过（含「已跟过+冷却中」「旧数据无字段」）。
