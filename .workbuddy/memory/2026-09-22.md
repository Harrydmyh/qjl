# 2026-09-22

## ★ 修复：同款跨桶合并 + 「同款 5 天内已开」不再开团

用户报：「还是发现有同个产品（不同供应商）重复开的情况」——要求
①同一商品（供应商不同也算同款）合并；②通过本工具开过的（open_log）5 天内的同款不再开团，
5 天以上可开。

### 根因（两条）
1. **去重是分桶各做一次**：`dedup_by_goods` 分别在 new / followed / reopen 上调用，
   同一款若同时落在「新活动」和「已跟过」里 → 两条都留下 → 会被开两次。
2. **5 天冷却只作用在 reopen 桶**（`hadHelpSale=True`），new / followed 完全不做冷却；
   而且冷却只按 actId + goodsId 匹配，**同款被别的供应商重新上架时 goodsId 会变 → 认不出来**。

### 改法
**core.py**
- 抽出 `_goods_groups(items)`（并查集：goodsId 有交集 **或** 归一化商品名相同 → 同一组）
  与 `_item_best(group)`；`dedup_by_goods` 改为两者组合。
- 新增 `_norm_name()`：去零宽字符 + trim（跨供应商同款常常只差零宽字符）。
- `_finish_fetch`：
  - 冷却表从两张变三张：`last_opened`(actId) / `last_opened_goods`(goodsId) /
    `last_opened_names`(归一化商品名)，判定取三者最晚。
  - **跨分桶合并**：三个桶合并起来跑一次并查集，被合并掉的来源记进 `altSources`
    （`[{ghName, category}]`），前端显示「同款另有 N 个来源」，不丢信息。
  - 给每条打 `recentlyOpened`（= daysSinceOpen < REOPEN_COOLDOWN_DAYS）。
    **不丢弃**：列表保留（灰标签），但开团范围与「可开团」筛选都排除它 —— 满 5 天自动恢复。
  - 唯一丢弃规则仍是「被帮卖过 + 5 天内我已开过」。
  - done 事件改为：`deduped`（合并总数）、`cooldown_count`、`cooldown_days`，
    去掉旧的 new_dup/followed_dup/reopen_dup。
- `parse_item` 新增 `goodsNames`（该活动**所有**商品名，归一化），供开团时写进日志。

**server.py**
- 开团成功写日志时同时记 `goodsIds` 与 `goodsNames`（从 activities.json 取）。

**index.html**
- 新增 `isRecentlyOpened()` / `isOpenBlocked()` / `skipBreakdown()` / `cooldownText()` / `CAT_LABEL`。
- `openableCount`、「开团状态」筛选、开团面板的 openIds/openSkipped 全部改用 `isOpenBlocked`。
- 列表行加黄标签「同款 N 天前已开」+ 合并提示「同款另有 N 个来源：xxx·新活动 / yyy·可复开」。
- 开团面板：这些行置灰 + 勾选框禁用；状态条显示
  「已跳过 N 个（323 个未开启跟团功能 · 3 个同款 5 天内已开）」；确认弹窗同步。
- 拉取日志文案改成「分桶 新 a / 已跟过 b / 复开 c → 同款合并 −d → 可用 K」。

## ★★ 用户给了个反例：「红豆的内衣这几天开了好几遍」→ 补上「包含匹配」

### 定性：这套数据正好命中精确同名匹配的盲区
同一款 `红豆10A满印莱卡180g套装` 在 3 个供应商那儿标题完全不同：
```
薛慢慢（薛瑞）/ 狂奔的小绵羊： 【光子抗菌技术】母婴A类❗️红豆10A满印莱卡180g套装
椰小服🥥：                    红豆10A满印莱卡180g套装          ← 少了前缀
```
而且日志显示**同一个活动 `2609180343564685` 在 9-19 被开了两次**
（16:48 → 新团 2609180853159054、20:49 → 新团 2609180946368248）。

**根因（旧代码）**：该活动 `hadHelpSale=False` + `isFollow=True` → 落进**「已跟过」桶**，
而冷却当时只管「可复开」桶 → 第二次拉到时又被开了。**红豆正是这个 bug 的活样本。**

### 改法：`_same_product()` 包含匹配
- `_norm_name` 从「只去零宽字符」升级为 **只保留中英文数字**（emoji/标点/空格全去）。
- 新增 `_SAME_MIN_LEN = 8` 与 `_same_product(n1, n2)`：完全相同 **或 短名被长名包含**（短名 ≥8 字）。
  长度门槛是防误合并的关键（「套装」「袜子」这类通用词只做精确比较）。
- 新增 `_containment_pairs(names)`：8-gram 索引预筛候选对，把 O(n²) 包含比较降下来。
- `_goods_groups()` 在「精确同名」之上再按包含关系 union。
- `_finish_fetch` 的 `_name_hit()`：商品名对已开名字做包含匹配；
  先把「已开名字表」限制在冷却窗口附近（`now - (5+9) 天`），避免日志增长拖慢拉取。
  **注意只跳过不更晚的候选**（`lt > hit` 短路），省掉大量 `_same_product` 调用。
