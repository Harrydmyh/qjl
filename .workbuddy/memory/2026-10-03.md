## 用户疑问：「昨天屏幕关掉了，显示没有成功发，但页面打勾且成功 82 个，是不是有问题？」

**结论：页面是对的，开团真的成功了 82 个，没有问题。** 用三份独立证据交叉验证过：

### 证据
1. **服务端任务记录还在内存里**（后端 PID 71476 从 10-02 10:06 起没重启过）：
   `GET /api/open/status` → `id=2, state=done, total=82, index=82, ok=82, fail=0, error=None,
   delay=360.0, jitter=5.0, created_at=2026-10-02 10:12:46, finished_at=2026-10-02 18:22:06,
   event_count=165`。
2. **`open_log` 里 10-02 共 83 条，全部 `status=ok`**（1 条是 10:11:52 的单开 + 82 条批量）。
   每条都有**非空且唯一**的 `newActId`（83 个 newActId 全不重复、actId 也全不重复）。
   关键：`newActId = result["data"]["actId"]`（`core.py:1110`，提交接口 `/activity-biz/help_sale_root/act/release`
   的响应）—— **这是平台返回的凭据，不是我们自己数的**。平台没建成功就不会有这个 ID。
3. **事件流 165 条（info 82 + ok 83），含「失败/错误/异常」的 0 条**。ok 事件形如
   `[1/82] ✓ 商品名 → 2609162218078041`。
4. **机器全程没睡**：相邻两条开团间隔 最小 56s / 中位 362s / 最大 369s，
   **没有一次 >15 分钟的断档** → 说明 8 小时里系统一直醒着（插电 `sleep 0`）。
5. **无重复开**：按 goodsIds 分组、按商品名统计，重复都是 0。

### 为什么"屏幕关掉"不影响
开团任务跑在 Python 服务进程里，**浏览器只是遥控器**（服务端 `_job_thread`）。
屏幕熄灭 ≠ 系统睡眠（插电时系统本来就永不睡）。

### 唯一真实存在的问题：**页面会误导**
页面与后端那条 fetch/轮询连接在屏幕熄灭、预览面板被挂起时会断，UI 就显示
`连接失败: TypeError: Failed to fetch`（`index.html:1120`）或「启动失败」——
但这只是**浏览器→服务端**的链路断了，**服务端照跑**。
用户看到的就是这个，容易误判成"没开成团"。
→ 待办（可选）：让页面重连后能明确显示「任务仍在后台运行」，别把链路断开说成任务失败。

## 追问「电脑关上以后还能发？」→ **合盖不行，昨天是熄屏没合盖**

用户以为自己是合了盖，实际不是。**四条独立证据**（都用只读命令查的）：

1. **`pmset -g log` 里 10-02 10:00~19:00 零条睡眠/唤醒记录** —— 窗口内最后一次睡眠是
   `09:16:52 Entering Sleep state due to 'Idle Sleep' ... Using Batt`，`09:42:11` 被 HID 唤醒；
   之后再没有一条 sleep/wake 记录。开团 10:12→18:22 全程**没睡过**。
2. **那时段日志里只有 `Using AC`（11 次）、`Using Batt` 0 次** → 插着电（AC `sleep 0`）。
3. **开团间隔最大 369s**（= 设定的 360s±5s），8 小时无断档 —— 睡着的机器不可能按 6 分钟节奏执行代码。
4. **`disablesleep` 从未设置过**（`pmset -g custom` / `pmset -g` 里都没有 → 值 0）；
   盖子状态 `ioreg ... AppleClamshellState = No`（当时是开着的）。
   → 若真合了盖，必然 clamshell sleep，会出现大断档，但没有。

**结论**：
- **熄屏（盖开着）+ 插电 → 任务照跑**（昨天 82 个就是这么发完的）。
- **合上盖子 → 默认必睡 → 任务停住**。睡醒后会从暂停处**接着跑**（不丢进度），
  但**正在发的那一条大概率失败**（HTTP 中断）；且睡多久任务就停多久。
- 想让合盖也能跑：`sudo pmset -a disablesleep 1` + 插电（`disablesleep` 在本机是有效键）。
- 判断「某段时间机器有没有睡」的可复用方法：`pmset -g log | grep -E "Entering Sleep state|Wake from"`，
  但**必须过滤掉 `Assertions` / `PreventSleep` 行**（那些不是真正的睡眠转折，容易误读）。
